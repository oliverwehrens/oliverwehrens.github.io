#Install the app

  1. Open the DMG and drag Daily Recall to Applications.
  2. Start Daily Recall from Applications. A new install opens the “Welcome to Daily Recall” window.

The app needs macOS 26 or later. It is signed with a Developer ID and notarized.

#The welcome window

The window has four rows. Each one opens the matching Settings pane:

RowOpensWhat to do
Grant permissionsSettings › PermissionsGrant Screen Recording and Accessibility
Connect a modelSettings › ModelEnter the base URL and run “Test Connection”
Tell it about youedits “About me” in placeA few sentences about your work (optional)
Review the promptsSettings › PromptsThe defaults work (optional)

Nothing is recorded until you select “Get Started”: no spans, screenshots or meetings, and the global hotkeys do nothing. “Get Started” is always enabled, whatever is still missing.

If you close the window instead, the menubar menu reads “Setup not finished” and offers “Finish Setup…”.

#Permissions

Daily Recall is not sandboxed. Settings › Permissions shows the state of each permission and opens the matching System Settings pane.

PermissionNeeded forWithout it
Screen Recordingscreenshotsno screenshots; activity tracking continues
Accessibilitywindow titlesonly app switches are recorded
Automation › Safari, Chrome, Bravethe active tab URLspans of that browser have no URL
Microphonedictationthe dictation hotkey shows a warning

In the order you meet them:

  1. Screen Recording. In Settings › Permissions, “Open Settings” adds Daily Recall to the list in System Settings › Privacy & Security › Screen Recording. Turn it on there. Daily Recall never asks at launch. macOS may ask you to confirm this permission again from time to time.
  2. Accessibility. Turn on Daily Recall in System Settings › Privacy & Security › Accessibility. The app picks it up within 2 seconds, without a restart.
  3. Automation. macOS asks the first time each browser is in front while Daily Recall is tracking. Change it later in System Settings › Privacy & Security › Automation.
  4. Microphone. macOS asks the first time you dictate. “Request Access” in Settings › Permissions asks ahead of time. Speech recognition needs no separate permission.

Meeting detection reads which app uses the microphone. That needs no microphone permission.

#Launch at login

Turn on “Launch at login” in Settings › General. A launch at login shows only the menubar icon. Starting the app from Finder or Spotlight opens the overview on today.

⌘Q closes the overview, Settings and meeting notes windows and keeps tracking in the menubar. “Quit” in the menubar menu exits.

#Web clip extension

The clipper works in Google Chrome and Brave.

  1. In Settings › Web Clips, select “Connect”. This installs the native messaging host that passes clips to the app.
  2. Open chrome://extensions or brave://extensions and turn on “Developer mode”.
  3. Select “Load unpacked” and choose the folder that “Show Extension in Finder” reveals: ~/Library/Application Support/Daily Recall/Browser Extension.
  4. Clip with the toolbar button or ⌥⇧C. Change the shortcut at chrome://extensions/shortcuts.

After an app update, select the extension’s reload button on the extensions page or restart the browser.

#Known limits

  • Web clips work in Chrome and Brave only, from the unpacked extension. Chrome shows its developer mode notice for it.
  • Safari private windows can’t be detected and are recorded like normal windows. Chrome and Brave incognito windows are recorded with the app name only.
  • A URL change without a title change, as in some single-page apps, does not start a new span.
  • Watching a video without keyboard or mouse input counts as idle after the idle threshold.
  • Only the new Teams app is detected as a meeting. A Teams device test that keeps the microphone open for 10 s is recorded as a meeting.
  • Opening a Bluetooth headset’s microphone for dictation switches it to a low-quality profile. This also affects a running Teams call.
